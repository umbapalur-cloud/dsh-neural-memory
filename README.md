# dsh-neural-memory · 神经持久化记忆

> 一个 Titans 风格的**关联记忆矩阵**，用它替代「什么都往向量库里塞」。
> 信息该不该被记住，由**惊讶度**（模型自己的预测误差）与**动量**决定；**打分与排序**长在权重里，
> 原文仍按条目表留存（见下方「实现口径」—— 它不是纯权重记忆）。
>
> **最新版：[v1.1.0 Release](https://github.com/umbapalur-cloud/dsh-neural-memory/releases/latest)**
> v1.1.0 新增：全生命周期自动接入（`agent/inbox/claimed` 静默观察 + `agent/pre-step` 三闸门静默联想 + `idle` 防抖落盘与轻量衰减）、Titans 惊讶动量 `S`、回忆加固 `recallBoost`、删除正交投影抹除、中英混合词界嵌入 `hybrid`、`dim: 128` 无损迁移、Float32 Base64 紧凑落盘（基准验收 **12/12** + 升级专项 **21/21** 全绿）。

**这是原型，不是论文复现。** 它证明的是「神经权重可以做持久记忆，且能用指标量化」，
不是「达到了 Titans 的效果」。所有数字见 [docs/DETAIL.md](docs/DETAIL.md) 的实测对照表，
未达标项见下方[已知限制](#已知限制实测)（**请先读那一节再决定要不要用**）。

## 它解决什么问题

长会话里最麻烦的不是「上下文不够长」，而是「**该记的没记住，不该记的占满预算**」。

- 把每句话都塞进向量库 → 检索质量随噪声堆积而下降，且每次都要做一次外部查表。
- 只保留最近 N 轮 → 早期的重要结论被无声丢弃。
- 靠人工写 memory 文件 → 要人来判断什么值得记，不可自动化。

本插件的判断标准是**可计算的**：一段文本进来，先用当前记忆矩阵预测「它应该长什么样」，
预测得越离谱 = 越意外 = 越值得记。完全熟悉的东西（重复内容）不占记忆预算。

## 工作原理（三句话）

```
嵌入    k, v = emb(text)          同一段文本永远得到同一对向量（n-gram 哈希，无随机）
惊讶度  surpriseAbs = ‖M·k − v‖²  当前矩阵对这句话的预测误差
        surpriseRel = 1 − cos(M·k, v)  预测方向偏离了多少
写入    两个都过关时：M ← M − η·∇L，∇L = 2(v̂−v)kᵀ     （一步梯度下降）
遗忘    nm_forget：M ← (1−decay)·M，条目强度同比衰减，低于 minStrength 的剔除
```

> ### ⚠️ 2026-11-17 三处重要修复（会改变你观察到的行为）
>
> **① 写入门限从单判据改成双判据。**
>   只判断对距离会有一个真 bug：`M` 被衰减后模长变小，`‖M·k − v‖²` 跟着变大
>   （实测衰减 8 轮后从 1.0000 降到 0.4352，**仍高于 θ=0.35**），
>   于是"自己刚忘掉的东西"被当成"新惊喜"重新写入。
>   现在要求 `surpriseAbs > θ` **且** `surpriseRel > 0.02` 才写。
>   `nm_observe` 的返回里 `surpriseAbs` / `surpriseRel` / `wroteAbs` / `wroteRel` 四个字段都能看到。
>
> **② `nm_recall` 自带召回真伪闸门（2026-11-17 晚重做）。**
>   原版只有一道**矩阵分数**阈值，实测拦不住无关内容：近似查询最低 0.481、
>   库外问题最高 0.632，两簇**区间重叠**，任何单一阈值都会要么漏召回要么误报 30%。
>   现在要求两道同时成立：`score >= minScore`（0.45，粗筛）**且**
>   `coverage >= minCoverage`（0.25，词面二元组覆盖，实测无关问题全部为 0）。
>   覆盖只在**排序之后**做闸门，排序仍然完全由 `M·k` 决定。
>   仍会报出 `top1Score` / `top1Coverage` 供判断；传 `minScore: -1` 可关掉全部过滤。
>   条目 `< minEntriesForTrust`（默认 10）时阈值统计意义不足，不过滤但会带 `note`。
>
> **④ 遗忘后可以重新学回（2026-11-17 晚修）。**
>   上一版的相对判据有副作用：条目被淘汰后 `M` 只等比缩小、方向不变，
>   再观察同一句话 `surpriseRel≈0` → 永远 `wrote=false`，条目再也回不来。
>   现在相对判据只对"**还在表里**的条目"生效；已淘汰的条目视为全新内容。
>
> **⑤ 并发与多实例写入不再丢条目（2026-11-17 晚修）。**
>   临时文件名加进程内自增序号（原来只用 pid+毫秒，同毫秒并发会撞名）；
>   同一 namespace 的落盘串行化；落盘前按 mtime 检测外部写入并合并条目。
>   实测：并发写 40 条，盘上从 37~39 条变为 40 条；两实例各写一条不再互相覆盖。
>
> **⑥ 判重不再把不同事实合并（2026-11-17 晚修）。**
>   「安然主要使用 C++」与「安然主要使用 C#」原来去标点后都变成 `c`，
>   被判成同一条。现在判重按**空白归一后的原文**哈希，
>   归一化（用于嵌入）也保留 `+ # . - _ / :` 这些有区分度的符号。
>
> **③ 落盘不再保存 k / v 原始向量（version 改为 2）。**
>   原实现把每条的 k 和 v 都写进 JSON，等于留了一条绕过 `M` 直接算 `cos(k_q, v_i)` 的路
>   （实测那样只有 20% 命中，但"看起来还能用"，矩阵会悄悄变成摆设）。
>   现在盘上只存 `text` + 元数据，`k`/`v` 在需要时用确定性哈希重算（内存里仍保留，供独立复算）。
>   40 条时落盘体积因此少了约 32 KB。
>
> ### 📌 实现口径（请按这个理解，别按"纯权重记忆"理解）
>
> 记忆由**两部分**组成：一张 `d×d` 关联矩阵 `M`（打分与排序，容量恒定 32 KB）
> 加一张**原文条目表** `entries`（保存原文，随条数线性增长，上限 `maxEntries=512`）。
> 召回时必须遍历条目表取原文，所以它**不是**"没有外部记录表的纯权重记忆"。
> 工具描述里原先那句"没有存一条记录的外部表"已被删除。
> 另外工具已改为注册前编译 `parameters`（宿主 `register()` 不编译作者侧 DSL），
> `nm_delete` 是新增的第 6 个工具（写墓碑防缓存回写）。

- `M` 是 `d×d` 的矩阵（默认 `d=64`，即 4096 个 float = 32 KB）。**矩阵本身大小与喂了多少条无关**；
  但完整的记忆还包括原文条目表，那张表随条数线性增长（上限 `maxEntries=512`）。
- `k` 与 `v` 用两套不同的 salt 做哈希，所以 `k` 与 `v` 近似正交——矩阵必须真的学一个
  「键→值」的映射，不能靠恒等变换蒙过去（这是**异联想**记忆，不是复制粘贴）。

## 六个工具

所有工具都返回带 `ok: boolean` 的对象，失败时带 `error: string`，**不会向模型抛异常**。

### `nm_observe` — 观察一段文本

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `text` | string | **必填** | 要观察的文本。超过 `maxChars`（默认 8000）会被拒绝 |
| `namespace` | string | `default` | 记忆分区，只允许 `[a-z0-9_-]{1,64}` |
| `surpriseThreshold` | number | 插件配置（0.35） | 绝对惊讶度门限，调高 = 更挑。传 `0` 表示强制写入 |
| `surpriseThresholdRel` | number | 插件配置（0.02） | 相对方向门限，配合上一项做双判据 |
| `minScore` | number | 插件配置（0.45） | 覆盖矩阵分数门限。传 `-1` 完全关掉过滤，拿原始候选（调试/消融用） |
| `minCoverage` | number | 插件配置（0.25） | 覆盖词面覆盖门限（0~1），召回的第二道真伪闸门 |

```jsonc
// 实际返回（首次出现的高信息量文本，其余字段省略）
{
  "ok": true,
  "wrote": true,                    // 这次真的更新了 M（= wroteAbs && wroteRel）
  "surprise": 1.0000000000000004,   // 保留旧字段名 = surpriseAbs，向后兼容
  "surpriseAbs": 1.0000,            // ‖M·k − v‖²  绝对预测误差
  "surpriseRel": 1.0000,            // 1 − cos(M·k, v)  预测方向偏离度
  "wroteAbs": true,                 // 绝对判据过没过
  "wroteRel": true,                 // 相对判据过没过
  "cosPredValue": 0.0,              // cos(M·k, v)，surpriseRel = 1 − 它
  "entries": 1,                     // 记忆条目总数
  "retained": true,                 // = wrote && inMemory
  "inMemory": true,                 // 这条文本当前是否在记忆表里
  "threshold": 0.35, "thresholdRel": 0.02,
  "namespace": "facts", "dim": 64,
  "writes": 1, "observes": 1, "weightBytes": 32768
}
```

> **`retained` 的口径**：`retained = wrote && inMemory`。
> 重复出现且已经学过的文本会得到 `wrote=false`、`inMemory=true`、`retained=false`。
> 想单看「现在还在不在表里」用 `inMemory`。

### `nm_recall` — 按权重召回

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `query` | string | **必填** | 查询文本 |
| `topK` | number | 5 | 返回条数，1~1000 |
| `minScore` | number | 插件配置（0.45） | 覆盖置信度阈值。传 `-1` 可强制绕过熔断 |
| `namespace` | string | `default` | |

> **置信度熔断（2026-11-17 起）**：最高分低于 `minScore` 时 `results` 直接返回空、
> `matched: false`，并报出 `top1Score` 和一句 `note`。
> 这样调用方不会拿到一堆低分噪音还以为召回了。
> 条目数 `< minEntriesForTrust`（默认 10）时跳过熔断——那时阈值不可靠。

```jsonc
// 40 条事实 / 查询「李曜辰的工号是 KX4821」的真实返回（results 只留前 2 条）
{
  "ok": true,
  "results": [
    { "text": "李曜辰的工号是 KX4821", "score": 0.7696239487254636, "surprise": 1.0000000000000004, "strength": 1.0000000000000004, "createdAt": 1794854712000 },
    { "text": "温梨落的工位有一盆绿萝",  "score": 0.3734760558544192, "surprise": 1.0126487641590818, "strength": 1.0126487641590818, "createdAt": 1794854712211 }
  ],
  "entries": 40, "topK": 5, "readoutNorm": 0.38348083514043685, "dim": 64, "namespace": "facts"
}
```

注意 `score` 的分布：正确的那条 `0.770`，第二名只有 `0.373`——**分离度很大**，
这也是原句查询能做到 100% 的原因。

打分完全来自矩阵：`score = cosine(M·k_query, v_entry)`。
有独立的消融证伪（`M` 清零 → 命中率 100% → 15%），见 DETAIL。

### `nm_forget` — 施加一轮遗忘

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `decay` | number | 插件配置（0.02） | 本轮衰减系数，0~0.999 |
| `namespace` | string | `default` | |

```jsonc
// 40 条事实、decay=0.3 跑一轮之后
{
  "ok": true,
  "entriesBefore": 40, "entriesAfter": 40, "decayed": true,
  "decay": 0.3, "evicted": 0, "decayRounds": 1, "namespace": "facts",
  "normBefore": 2.313852662897624, "normAfter": 1.619696864028334
}
```

> `‖M‖` 正好乘了 `0.7`（`2.313853 × 0.7 = 1.619697`）。
> 条目没被淘汰是正常的：条目强度初值 ≈ 1，衰减到 `minStrength=0.05` 还要很多轮。

### `nm_status` — 查看形态

```jsonc
// 40 条事实的真实返回（namespaces / storageRoot / updatedAt 等已省略）
{
  "ok": true, "entries": 40, "weightBytes": 32768,
  "entriesBytes": 44662, "stateBytes": 77430,
  "meanSurprise": 1.038905, "highSurpriseEntries": 40, "decayRounds": 0,
  "dim": 64, "eta": 0.2, "decay": 0.02, "surpriseThreshold": 0.35,
  "norm": 2.313853, "namespaces": ["facts"]
}
```

### `nm_export` — 导出快照

```jsonc
// 40 条事实的真实返回
{ "ok": true, "path": "<state>/exports/facts.json", "entries": 40, "bytes": 233028, "namespace": "facts", "dim": 64 }
```

空 namespace 导出会返回 `ok:false`（「没有任何记忆条目，无可导出内容」），
避免凭空造出一个快照文件、让「这个 namespace 存在吗」变得不可答。

## 怎么用（完整命令序列）

### 装进 DSH

```powershell
# 进入插件目录
cd <本包路径>
```

用 `plugin_manager` 安装，`target` 传插件目录绝对路径（本地目录是 link 安装）：

```jsonc
{ "action": "install_bundle", "target": "<本包路径>" }
```

> ⚠️ 装完**不要**手改 profile 的 `package.json`，**不要**跑 `pnpm/npm install`。

### 配置（`cordis.patch.yml` · v1.1.0 推荐生产配置）

```yaml
config:
  dim: 128                    # 记忆矩阵维度，8~256（v1.1.0 默认升维至 128，开启 migrateOnDimChange 可无损迁移旧库）
  eta: 0.2                    # 写入步长，必须 < 0.5（2η<2 才不发散）
  momentum: 0.25              # Titans 惊讶动量系数（0 关闭；>0 保留梯度动量 S）
  embedMode: hybrid           # ngram（基准兼容）或 hybrid（中英词界混合 + 标识符加权 + 次线性 TF）
  recallBoost: 0.15           # 回忆巩固强度（每次高置信召回轻度强化对应权重）
  surpriseThreshold: 0.35     # 写入门限
  decay: 0.02                 # nm_forget 默认衰减
  minStrength: 0.05           # 条目强度低于此值被淘汰
  maxEntries: 512             # 条目表容量上限
  maxChars: 8000              # 单条文本字符上限
  storageFormat: base64       # Float32 Base64 紧凑落盘（兼容旧 JSON 读取）
  persistDebounceMs: 1500     # 写入防抖合并窗口（idle / dispose 自动 flush）
  migrateOnDimChange: true    # dim 或 embedMode 升级时无损重嵌重学旧条目
  autoObserve: true           # 接入 agent/inbox/claimed 静默自动观察
  autoRecall: true            # 接入 agent/pre-step 三闸门静默自动联想（不匹配 0 字节打扰）
  autoForgetEveryTurns: 12    # 每 12 个 idle 回合执行一次轻量衰减（0.015）
  path: null                  # 覆盖存储目录，null = <DSH_HOME>/state/dsh-neural-memory
```

### 典型调用序列

```
nm_observe  { "text": "李曜辰的工号是 KX4821" }
nm_recall   { "query": "李曜辰的工号", "topK": 5 }
nm_status   { }
nm_forget   { "decay": 0.05 }
nm_export   { }
```

会话结束前不需要做什么——`M` 与条目表**每次 observe / forget 后立即原子落盘**
（`.tmp` → `rename`），下次启动自动读回。

### 数据落在哪

```
<DSH_HOME>/state/dsh-neural-memory/<namespace>.json        # 状态（M + 条目表）
<DSH_HOME>/state/dsh-neural-memory/exports/<namespace>.json # 导出快照
```

`DSH_HOME` = `process.env.DSH_HOME || ~/.dsh`。文件名只允许 `[a-z0-9_-]{1,64}`，防路径穿越。

### 自己跑验收

```powershell
node ./tests/run.mjs       # 12/12 严格数学与工程验收基准
node ./tests/upgrade.mjs   # 21/21 v1.1.0 升级与全生命周期验收

```

## 与 RAG 的本质区别

| | RAG（向量库） | 本插件（神经记忆） |
|---|---|---|
| 记忆存在哪 | 外部数据库，一条条记录 | `d×d` 权重矩阵，信息混合在参数里 |
| 容量 | 随条目线性增长 | **恒定 32 KB**（`d=64`），与条数无关 |
| 写不写 | 全量写入，靠事后检索过滤 | **写前筛选**（惊讶度门限），不意外的根本不占地方 |
| 遗忘 | 手动删记录 | 权重衰减，自然消融（`M ← (1−decay)M`） |
| 读出 | 最近邻检索 | `v̂ = M·k` 一次矩阵向量乘 |
| 多段记忆的融合 | 各条独立，检索后拼上下文 | **天然叠加**在同一张矩阵里（会互相干扰，见限制） |
| 可解释性 | 高（能列出命中了哪条） | 低（只能看到余弦分数，看不到「为什么」） |

**一句话**：RAG 是「把书放进书架，用的时候去找」；这里是「把书读进脑子，用的时候凭印象」。
前者精确但容量线性、无筛选；后者恒定开销、有筛选，但会记混、会忘、不可审计。

## 已知限制（实测）

> 以下每一条都来自 `tests/run.mjs` 的**真实输出**，不是推测。完整日志见 DETAIL 的实测对照表。

### 1. 「按意思像不像」曾是夸大宣传 ⚠️ 最重要的限制

**这条限制的来历值得记下来**，因为它比数字本身重要。

最初 `nm_recall` 的工具描述写着：「分数完全来自矩阵乘法，不做任何字符串/关键词匹配——
**所以它按「意思像不像」排，而不是「有没有出现这个词」**。」

前半句为真，**后半句的推论不成立**。独立验收者拿四档难度的查询去攻，真语义档全军覆没，
把这条判成「说明书比能力大」。这个判断是对的——而且它说明**代码 bug 会报错，宣传口径不会**：
调用它的模型读了这句话就去做语义查询，拿到一堆噪音还以为是对的，它不会知道自己被误导了。

描述已改成如实版本（见上「能力边界」）。下面保留两套独立实测，因为**它们互相修正了对方的漏洞**：

| 查询类型 | 验收者测（his cases） | 作者复测（his cases） |
|---|---|---|
| 原句截断（保留人名与主体词） | 10/10 = 100% | 8/10 = 80% ¹ |
| 只给唯一实体串（`KX4821` / `CA1832`） | 7/8 = 87.5% | 8/8 = 100% |
| 改写但**共享实词**（"谁会写 Rust"） | 4/6 = 66.7% | 6/6 = 100% |
| 「真语义」 | 0/4 = 0% | 1/6 = 16.7% ² |

¹ 作者的用例里混入了「张伟的生日是」「冯雪在深圳」这类**砍掉全部实词只剩虚词骨架**的查询，
它们的失败是真实的（top1 分数 0.40，正好卡在阈值下）。

² **这里作者纠正了验收者的一个方法论问题**：验收者的「真语义」用例
（记的是「岳临川擅长写 Rust」，问「谁最擅长编程语言」）**并不是纯语义**——
它和原句共享「编程语言」四个字，命中的是字符串重叠，不是语义。
剔除这类污染后换成真正零实词重叠的 6 条，得到 1/6。

**所以正确结论是**：语义查询**基本不行，但不是数学上的 0**——极偶然地会撞上一条。
**方向没变，但「0%」这个数字是运气，不是规律。**

**结论**：它是**精确/近精确查找**，不是语义检索。查询里最好带上原句的主语或唯一标识符。
真正的语义理解需要神经网络嵌入模型，本插件（零依赖纯 JS）做不到。

**失败是静默的**：召不回时不报错，照样返回 topK 条低分噪音。所以描述里给了一个自查信号：
**top1 的 score < 0.45 基本就是没召回**（40 条记忆下实测判别准确率 96.7%，5 折留出验证）。
但**记忆条数很少（≤10 条）时这个阈值会失效**，那时语义查询也可能拿到 0.40~0.53 的假高分。

> 顺带一条方法论教训：作者曾试过用 `readoutNorm` 当置信度信号（直觉上更"干净"，
> 原句 0.395 vs 语义 0.067），实测只有 86.7%，比 topScore 差。**直觉输了，按数据选了 topScore。**

### 2. 默认门限下，重复内容仍然会写

40 条事实学完一轮后再全部观察一遍：**40/40 条仍满足 `surprise > 0.35`**，全部再次写入。

原因是干扰：40 条互相改写同一个 `M`，重看第 1 条时误差又被抬回门限以上。
只有 5 条的小规模下会正常收敛（第 3 次起 `wrote 0/5`）。

门限扫描（`M` 固定在「学完 40 条」后）。下表是**两套独立测试**的结果——验收者与作者各跑了一遍，
用例不同所以数字有差异。**两者都列出来**，因为它说明这个数字高度依赖事实之间的相似度，
不该被当成精确刻度：

| θ | 验收者测（40 条） | 作者复测（同一批 40 条） |
|---|---|---|
| 0.35（默认） | 40/40 = 100% | 40/40 = 100% |
| 0.50 | 12/40 = 30% | 24/40 = 60% |
| 0.60 | 2/40 = 5% | 3/40 = 8% |
| 0.70 及以上 | 0/40 = 0% | 0/40 = 0% |

**建议**：记的条数超过 ~20 条时，把 `surpriseThreshold` 提到 `0.6~0.7`。
**只记这个区间，不要记具体分数**——换一批事实，中间两档能差一倍。
（0.35 和 0.70 两档两套测试完全一致，这两个端点是可靠的。）

### 3. 容量有限，规模上去召回率会掉

`d=64`、单步 `η=0.2`、默认门限下。同样列出**两套独立测试**：

| 记忆条数 | 验收者测 | 作者复测（真实多样事实） |
|---|---|---|
| 20 | 100% | 100% |
| 40 | 100% | 100% |
| 80 | 81.3% | 100% |
| 160 | 84.4% | — |
| 320 | **65.6%** | **75%** |

**两条曲线差 10~19 个百分点，但趋势一致**：过了 100 条就开始掉，300 条级掉到 65~75%。
所以可靠的说法是「**100 条以内基本无损，300 条级会丢两成到三成半**」，不要引用单个精确值。

⚠️ 作者在这里踩过一个坑，值得记下来：最初用程序生成的合成事实
（`赵伟的工号是A731000` 这种）跑容量测试，320 条只有 30%，差点写进文档。
**那是测试本身不公平**——合成事实彼此太像，本质上是在考「能不能分辨孪生兄弟」。
换成真实多样的事实后是 75%。这一点也是下面「惊讶度/容量数字极依赖用例相似度」的由来。

条目表最多 512 条（`maxEntries`），但**召回质量在 100 条以上就开始明显下滑**。
它的定位是「短中期工作记忆」，不是「长期知识库」。

### 4. 一次只学一步，学得慢

每次 `observe` 只做**一步**梯度下降（`η=0.2`），误差约按 `×(1−2η)=0.6` 收缩。
所以需要多轮才能「学会」；同一句话连续观察 2~3 次才会稳定停止写入。

### 5. 单条文本上限 8000 字符

超过直接 `ok:false` 拒绝（防止 1MB 文本把主线程拖死）。
长文档需要先切分。1MB 文本实测：`ok:false, error="text 过长（1048576 字符 > 上限 8000）"`。

### 6. 改 `dim` 会让已有记忆全部失效

`dim` 变了之后旧矩阵与旧嵌入空间不兼容，读盘时会**整体丢弃**（实测：`dim` 64→32 后 `entries=0`，
不产出 NaN）。这是有意的安全降级，但也意味着改配置 = 清空记忆。

### 7. 每个 namespace 一份独立矩阵，不共享

`alpha` 学到的内容不会帮到 `beta`。这是刻意的隔离（防止串味），
代价是不能「跨领域迁移」。

### 8. 遗忘会连矩阵一起衰减

`nm_forget` 不只是删条目，`M` 本身也在乘 `(1−decay)`。
衰减过头之后即使条目还在，读出也接近 0（实测 `decay=0.3` × 12 轮后 `‖M‖` 从 0.9648 掉到 0.0134）。
这是「遗忘」的设计，但如果你只想删几条记录，它不是合适的工具。

`tests/run.mjs` 的 **12 个小节全部通过，退出码 0**。
