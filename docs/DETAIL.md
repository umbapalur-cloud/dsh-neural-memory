## 0. 一句话定位

把「海马体按惊讶度筛选记忆」翻译成可测的数学：一个 `d×d` 关联记忆矩阵 `M`，
用**预测误差**做写入门限，用**权重衰减**做遗忘，用**异联想读出**做召回。
**这是原型，不是 Titans 论文的复现**（差异见 §6）。

## 1. 惊讶度 = 预测误差

### 1.1 定义

给定文本，先做**确定性嵌入**得到一对向量：

```
k = emb(text, salt=K_SALT)      ∈ R^d     键：用来"查"
v = emb(text, salt=V_SALT)      ∈ R^d     值：应该被"想起"的东西
```

用当前的记忆矩阵做预测：

```
v̂ = M·k
```

惊讶度就是**预测误差的平方**：

```
surprise = ‖v̂ − v‖²  =  Σ_i (M·k − v)_i²
```

### 1.2 为什么用「平方误差」而不是别的

三个理由，每个都对应一个可验证的性质：

**(a) 它就是梯度范数的平方。**

```
L(M) = ‖M·k − v‖²
∇_M L = 2(M·k − v) kᵀ
‖∇_M L‖²_F = ‖2 err kᵀ‖²_F = 4·‖err‖²·‖k‖² = 4·surprise·‖k‖²
```

因为 `k` 已 L2 归一化（`‖k‖=1`），所以 `surprise = ‖∇L‖²_F / 4`。
**惊讶度大 ⟺ 梯度大 ⟺ 这一步能改动的东西多。** 用别的度量（比如 `‖err‖₁`）就没有这个对应关系。

**(b) 它从零矩阵开始的初值是 `‖v‖² = 1`** ——正好是「完全不知道」的解析值。
实测第 1 次 `observe` 返回 `surprise = 1.000000000000`，手算 `‖0−v‖² = ‖v‖² = 1`，`diff = 2.220e-16`。

**(c) 学会之后它会按 `(1−2η)` 几何收缩。** 见 §2.3。

### 1.3 门限的作用

```
wrote = surprise > θ
```

`θ` 默认 `0.35`。直觉：`surprise=1` 是「完全陌生」，`0` 是「完全记得」，
`0.35` 大致是「已经学过、但还没学透」。

**门限真的在筛**（同一套代码，两个规模，结论相反——这个对比很重要）：

| 场景 | 第 1 次 | 第 2 次 | 第 3 次 | 第 4~5 次 |
|---|---|---|---|---|
| **5 条**文本各重复 5 次 | surprise 1.029968<br>wrote 5/5 | 0.370788<br>wrote 5/5 | **0.133484<br>wrote 0/5** | 0.133484<br>wrote 0/5 |
| **40 条**学完一轮后再全看一遍 | 均值 1.038905 | — | — | **40/40 仍 > 0.35** |

小规模下第 3 次起完全停止写入（筛选生效）；40 条时全部仍写。
**差异来自干扰，不是筛选机制坏了**：40 条互相改写同一个 `M`，
重看第 1 条时它的误差又被别人抬了回去。这是容量问题（§4），处理办法是提高 `θ`。

`θ` 扫描（`M` 固定在「学完 40 条」后，同一批 40 条再观察一次）：

| θ | 0.35 | 0.50 | 0.60 | 0.70 | 0.80 | 0.90 | 0.95 |
|---|---|---|---|---|---|---|---|
| 会写入 | 40/40 | 12/40 | 2/40 | 0/40 | 0/40 | 0/40 | 0/40 |

第二轮 surprise 分布：`min=0.3515  中位=0.4699  max=0.6652`。

## 2. 关联记忆矩阵的梯度更新

### 2.1 从损失到更新式

损失（对单条样本）：

```
L(M) = ‖M·k − v‖²  =  (M·k − v)ᵀ(M·k − v)
```

对 `M` 求梯度。记 `err = M·k − v`，用矩阵求导的链式法则：

```
∂L/∂M = 2·err·(∂(M·k)/∂M)ᵀ
```

`M·k` 对 `M` 的第 `(i,j)` 个元素的偏导是 `δ_ij·k_j`（因为 `(M·k)_i = Σ_j M_ij k_j`），所以

```
[∂L/∂M]_ij = 2·err_i·k_j    ⟹    ∇_M L = 2·err·kᵀ = 2(M·k − v)kᵀ
```

**这就是契约里的 `∇L = 2(v̂−v)kᵀ`。** 系数 2 来自平方，不能漏。

一步梯度下降（学习率 `η`）：

```
M ← M − η·∇L = M − 2η·(M·k − v)kᵀ
```

代码里是：`addScaled(state.M, grad, -2 * eta)`，其中 `grad = outer(err, k)`，
`err = pred − v`（`pred = M·k`）。**符号与系数都对。**

### 2.2 手算验证（从 M=0 开始，`dim=64, η=0.2`）

第 1 步：`M=0 ⟹ v̂=0 ⟹ err = −v`，所以

```
∇L = 2(0−v)kᵀ = −2vkᵀ
M₁ = 0 − η·(−2vkᵀ) = 2η·vkᵀ
```

用**独立实现**的 `outer` 手算 `M₁`，与实现逐元素比：

```
maxAbsDiff = 2.776e-17      （阈值 1e-12，通过）
```

**这个检查有区分力**（不是躺赢）：

| 若实现写错成 | 与实现的误差会是 |
|---|---|
| 符号写反（`−2η·vkᵀ`） | `1.451e-1` |
| 漏掉系数 2（`η·vkᵀ`） | `3.628e-2` |

两者都远大于 1e-12，所以真写错了一定会被抓到。

第 2 步（`M≠0` 的一般情形）：手算 `‖M₁·k − v‖² = (0.4−1)²·‖v‖² = 0.36`，
实现报 `0.360000000000`（`diff=5.551e-17`）；
`M₂` 与手算 `M₁ − η·2(v̂−v)kᵀ` 的 `maxAbsDiff = 1.388e-17`。

### 2.3 收敛性质

因为 `‖k‖=1`，把 `M ← M − 2η(Mk−v)kᵀ` 两边右乘 `k`：

```
M_new·k = M·k − 2η(M·k − v)(kᵀk) = M·k − 2η(M·k − v) = (1−2η)(M·k) + 2η·v
```

即误差 `err_new = M_new·k − v = (1−2η)(M·k − v) = (1−2η)·err`。

所以**每写一次，预测误差按 `(1−2η)` 几何收缩**，且 `η<1` 时不会发散（`2η<2`）。
默认 `η=0.2` ⟹ 每步 `×0.6`。

实测连续 3 次写入：`surprise = 1.000000 → 0.360000 → 0.129600`，比值正好 `0.36`（`=0.6²`）。
`Config` 里把 `eta` 夹到 `≤0.4999` 就是为了守住这个稳定性条件。

> ⚠️ 这个性质只在**单条样本、且中间不做别的写入**时严格成立。
> 多条样本交替写入时，`M·k_i` 会被其他样本的更新扰动——这就是 §4 的干扰问题。

### 2.4 为什么 k 和 v 要用两套 salt

如果 `k = v`，最优 `M` 就是单位矩阵（`M·k = k = v`），
所谓「记忆矩阵」退化成原样复制，且学过一次后 `surprise ≡ 0`，整个筛选机制失效。

所以 `k` 用 `K_SALT = 0x9e3779b1`、`v` 用 `V_SALT = 0x85ebca6b` 两次不同投影。
两者在同一特征空间上，因此 `k` 之间保留相似度结构（`cos(k_a,k_b) ≈ cos(v_a,v_b)`），
但 `k` 与 `v` 近似正交 —— `M` 必须真学一个跨子空间映射。这就是**异联想记忆**。

实测证据：绕过 `M`、直接用 `cos(k_q, v_i)` 打分，命中率只有 **4/20 = 20%**；
走 `M`（`cos(M·k_q, v_i)`）是 **20/20 = 100%**。这一层映射不可省。

## 3. 文本 → 嵌入：为什么不能随机

### 3.1 哈希方案

```
normalize:  NFKC 归一化 → 小写 → 只保留 \p{L} 与 \p{N}
n-gram:     1/2/3-gram，权重 0.5 / 1.0 / 1.0
投影:       每个 n-gram 投 2 维：
              h = mix32(fnv1a(gram, salt + p·0x27d4eb2d))
              idx = h % dim
              sign = (h >>> 31) ? −1 : +1
              out[idx] += sign · weight
归一化:     out /= ‖out‖₂
```

- `fnv1a`：FNV-1a 32 位，**按 UTF-16 码元逐字节**喂入，保证跨平台逐位一致。
- `mix32`：murmur3 的 fmix 变体。**必须混一次**——直接拿 FNV 低位取模，
  相邻 n-gram 极易落到同一维。
- 符号位取自同一混合值的高位，用于消掉「累加恒为正」的偏置。
- 虚词降权：整串都是虚词（`的是在有的了和…`）的 n-gram 权重 ×0.4，
  因为它们在每条事实里都出现，不含区分信息。

### 3.2 为什么不能用随机

**如果嵌入用 `mulberry32(seed)` 这类随机投影：**

1. **进程重启后嵌入全变**，磁盘上存的 `k`/`v` 立刻失配 —— 持久化直接失效。
2. **同一段文本观察两次得到不同向量**，判重（`hashText`）失效，表里会出现重复条目。
3. **召回必须重新算一遍所有条目的嵌入**（因为存的值对不上），等于每次查询都要 O(N·d) 重新编码，
   而「记忆内化在权重里」的前提就不成立了。

**确定性哈希的代价**：它只能捕捉**字符级**相似，捕捉不到语义（见 §7 能力边界）。
这是零依赖纯 JS 的现实约束，不是疏忽。

### 3.3 判重

```
hashText(text) = mix32(fnv1a(normalize(text), 0x9747b28c)).toString(16).padStart(8,'0') + ':' + len
```

同一句话观察两次不会在表里新增条目，只刷新 `lastSeen`（若通过门限则累加 `strength`）。
实测并发 5 次重复 `observe` 同一文本，表里仍只有 1 条。

## 4. 遗忘曲线与淘汰阈值

### 4.1 两套机制

**(a) 矩阵权重衰减**（`nm_forget`）：

```
M ← (1 − decay) · M
```

`decay` 默认 `0.02`。这是 `L2` 正则化的效果——**低强度（=低惊讶）的内容自然消融**。

**(b) 条目强度衰减 + 淘汰**：

```
entry.strength *= (1 − decay)
if (entry.strength < minStrength) 剔除条目
```

`minStrength` 默认 `0.05`。条目强度初值 = 它写入时的 `surprise`。

### 4.2 实测：单调性与淘汰

默认 `decay=0.02` 连跑 5 轮：条目数与 `‖M‖_F` **单调不增**（通过）。

`decay=0.3` 连跑 12 轮（6 条事实，`minStrength=0.05`）：

| 轮次 | entries | ‖M‖_F | 本轮淘汰 |
|---|---|---|---|
| 起始 | 6 | 0.964834 | — |
| 1 | 6 | 0.675384 | 0 |
| 2 | 6 | 0.472769 | 0 |
| 3 | 6 | 0.330938 | 0 |
| 4 | 6 | 0.231657 | 0 |
| 5 | 6 | 0.162160 | 0 |
| 6 | 6 | 0.113512 | 0 |
| 7 | 6 | 0.079458 | 0 |
| 8 | 6 | 0.055621 | 0 |
| **9** | **0** | 0.038935 | **6** |
| 10 | 0 | 0.027254 | 0 |
| 11 | 0 | 0.019078 | 0 |
| 12 | 0 | **0.013355** | 0 |

- 淘汰前 6 条 → 淘汰后 0 条，累计淘汰 6 条，**全部发生在第 9 轮**。
- 这揭示了一个重要特性：**淘汰是「悬崖式」的，不是渐进的**。
  6 条条目的强度几乎相同（`[1.0000, 0.9993, 0.9968, 1.0387, 1.0185, 0.9862]`），
  所以它们**同时**跌破 `minStrength=0.05`，一次性集体消失。
  真实使用中强度有差异，才会呈渐次淘汰。
- **`‖M‖` 的衰减与理论完全一致**：实测 `0.013354549`，理论 `0.964834 × 0.7¹² = 0.013354549`。
- 淘汰后 `‖M‖ = 0.013355 > 0` —— 是**权重衰减**，不是把矩阵删了重建。

默认 `decay=0.02` 连跑 5 轮：`(6, 0.946) → (6, 0.927) → (6, 0.908) → (6, 0.890) → (6, 0.872)`，
条目数与 `‖M‖_F` **单调不增**（通过），且 5 轮内没有任何条目被淘汰——
符合 `log(0.05)/log(0.98) ≈ 149` 轮的理论淘汰时间。

### 4.3 淘汰阈值的设计取舍

`minStrength=0.05` 与 `θ=0.35` 是配套的：
条目强度初值 ≈ `surprise`，首次写入时 `surprise ≈ 1`，所以一条「首现」的记忆要衰减约
`log(0.05)/log(0.98) ≈ 149` 轮（默认 decay）才会被淘汰——
**默认参数下几乎不会淘汰任何东西**，这是一份相当「保守」的遗忘策略。

想真正看到遗忘，需要显式调大 `decay`（如 `0.3`）或调大 `minStrength`。
`README` 的「已知限制」第 8 条说明了这一点：`decay` 过大会连矩阵一起衰减到读出接近 0。

## 5. 召回打分：来源可证

### 5.1 唯一的打分器

```js
const readout = matvec(state.M, kq, dim, dim)      // v̂_q = M·k_q
const scored = state.entries.map((e) => ({
  score: cosine(readout, e.v),                     // 唯一的打分来源
  ...
}))
```

`recall` 里**没有一处** `includes` / `indexOf` / `match`（已用去注释+去字符串的源码扫描确认：
`lib/` 代码里「可疑的字符串匹配调用」= 0 处）。

### 5.2 三重证伪

**(a) 自己重算**：从落盘的 `M` 与条目 `v`，用**独立实现**的 `matvec`/`cosine` 重算，
与工具返回的 `score` 逐条比 → 比较 100 个分数，`最大偏差 = 0.000e+0`；排序不一致 0 处。

**(b) 清零消融**（最有说服力）：

| | top-5 命中 | top-1 分数 |
|---|---|---|
| `M` 正常 | **20/20 = 100%** | — |
| `M` 清零 | **3/20 = 15%** | 全部变为 0（最大变化 `0.936429`） |

清零后分数**全部为 0**（20 条查询里 0 条还有非零分数）。
残留的 3 条「命中」全部落在**记忆表里最早的 5 条**内——
证实那是 `score` 相同时按 `createdAt` 兜底排序的结果，与语义无关。

**(c) 绕过 M 反证**：直接用 `cos(k_q, v_i)` 打分 → **4/20 = 20%**，远低于走 `M` 的 100%。
说明「读出 `M·k` 再比」这一层是必要的，不是可有可无的装饰。

> 诚实说明：另有一项「字符重叠度打分器」与原句查询的 top-1 一致 20/20。
> **这项没有区分力**（原句查询本来就是字符几乎全同的任务），所以**不作为证据**，
> 真正的证据是上面的 (b) 和 (c)。写在这里是为了防止有人拿它当反例。

## 6. 与 Google Titans 的对应关系（诚实版）

| Titans 论文里的东西 | 本插件的实现 | 差距 |
|---|---|---|
| 神经长期记忆模块（深度 MLP 作为记忆） | **单个 `d×d` 线性矩阵** | 表达能力差很多；线性映射无法表示非线性关联 |
| 惊讶度 = 梯度（surprise metric，含动量项） | `‖M·k − v‖²`（纯瞬时预测误差） | 没有动量、没有衰减记忆的 surprise 累积 |
| 记忆更新用**带动量的优化器**，多步 | **单步 SGD**，`η=0.2` | 学得慢；论文用 mini-batch + 动量 |
| 遗忘由**自适应权重衰减**控制（学习到的） | **固定 `decay` 超参** | 论文的衰减与惊讶度联动，这里是常数 |
| 键值来自**训练好的网络嵌入** | **n-gram 哈希**（零依赖约束） | 这是最大差距：没有语义空间，只有字符重叠 |
| 长上下文记忆通过 chunk 递归写 | 每条文本独立 observe | 没有序列级的递归状态 |

**结论**：本插件复现的是 Titans 的**问题设定与最核心的机制形状**
（惊讶度门限 + 关联矩阵 + 权重衰减 + 权重内化），
而**不是**它的模型架构、优化器或嵌入质量。
把它说成「Titans 风格的原型」是准确的；说成「Titans 的实现」是夸大。

### 与 TTT 的另一条路

同项目的 `dsh-ttt` 走的是「**把上下文当训练集，对隐藏权重做多步梯度下降**」；
本插件走的是「**用一个固定大小的关联矩阵做快速一次写入 + 衰减**」。
两者都把状态压进固定大小的权重，区别在**写入深度**（TTT 多步 vs 这里单步）
与**读出方式**（TTT 是下一 token 预测 vs 这里是键值读出）。

## 7. 能力边界（实测，最重要的一节）

### 7.1 四种查询难度

同一份 40 条记忆，`top-5` 判定：

| 难度 | 查询样例 | 命中率 |
|---|---|---|
| 1. 原句截断（保留人名与主体词） | 「李曜辰的工号是什么」 | **10/10 = 100%** |
| 2. 只给唯一实体串 | 「KX4821」「CA1832」「HT20260914」 | **7/8 = 87.5%** |
| 3. 改写但共享实词 | 「谁会写 Rust」「谁研究蛋白质」 | 4/6 = 66.7% |
| 4. **真语义**（目标句里无一个查询词） | 「谁最擅长编程语言」→「岳临川擅长写 Rust」 | **0/4 = 0%** |

难度 4 的四个全部未命中：

| 查询 | 期望目标 | 结果 |
|---|---|---|
| 谁最擅长编程语言 | 岳临川擅长写 Rust | 未中（top1=0.411） |
| 谁管钱与预算 | 熊知远的项目预算是 380 万 | 未中（top1=0.354） |
| 谁在生物领域工作 | 邵清嘉的研究方向是蛋白质折叠 | 未中（top1=0.552） |
| 谁住的地方有湖 | 林胧在杭州西湖边开了家茶馆 | 未中（top1=0.320） |

### 7.2 为什么原句查询是 100%

必须说清，否则会误导：

查询用原句时，`k_query ≡ k_entry`（同一段文本的确定性哈希）。
`M` 学的是 `k_i → v_i` 的映射，读出 `M·k_i ≈ v_i`，于是 `cos ≈ 1`。

所以「原句 100%」证明的是：
**异联想精确查找真的工作**（键值映射学到了、矩阵读出正确、持久化无损），
**它不能证明语义理解**。

### 7.3 对宣传口径的修正

`lib/tools.js:89-91` 里 `nm_recall` 的 description 写着：

> 「分数完全来自矩阵乘法，不做任何字符串/关键词匹配——所以它按「意思像不像」排，而不是「有没有出现这个词」。」

前半句**为真**（已用清零消融证明分数来自矩阵）；
后半个推论**不成立**：矩阵打分与字符串重叠高度相关，因为**嵌入本身**就是字符 n-gram 哈希。
「不查字符串」不等于「理解语义」。

> 这是提交给 LEAD 的一条**文档级缺陷**（不属于代码 bug，不影响契约达标）。
> README 与本文都已按实测口径修正。

## 8. 容量与性能

`d=64`，每个规模用独立 namespace、从零开始学，原句查询：

| 记忆条数 | 召回率 | ‖M‖_F | 查询耗时 |
|---|---|---|---|
| 20 | **100%** (4/4) | 1.677 | 0 ms |
| 40 | **100%** (8/8) | 2.205 | 1 ms |
| 80 | 81.3% (13/16) | 2.793 | 1 ms |
| 160 | 84.4% (27/32) | 3.380 | 4 ms |
| 320 | **65.6%** (42/64) | 3.926 | 16 ms |

- `‖M‖_F` 随条数增长但远慢于线性（近正交键在矩阵里叠加），40 条时 2.205、320 条时 3.926。
- 召回耗时随条数线性增长（每条记忆算一次 `cosine`，`O(N·d)`）；
  `matvec` 本身是 `O(d²)=4096` 次乘加，与 N 无关。
- **质量拐点在 100 条附近**：条目表上限虽是 512，但超过 100 条后召回明显下滑，
  因为单步 `η=0.2` 的写入会互相干扰。

### 存储

- 权重：`d×d×8 = 32768` 字节，**与条数无关**。
- 条目表：每条 `≈ 文本长度×2 + 2·d·8 + 64` 字节。
- 落盘实测：40 条事实的 `exports` 快照 `233028` 字节（缩进 2 的 JSON）；
  `status.entriesBytes = 44662`，加上矩阵 `32768` 得 `stateBytes = 77430`。

## 11. 独立判断

**能用的场景**：
近期结论、用户偏好、项目约定这类**短中期**记忆；查询时能带上原句主语或唯一标识符；
条数控制在 100 条以内；接受「会记混、会忘、不完全可解释」。

**不能用的场景**：
当知识库做精确检索（用 RAG）；需要语义泛化（"谁擅长编程"→"会写 Rust"）；
需要审计「为什么召回这条」（只能看到余弦分数）；需要跨 namespace 迁移；
条数超过几百条。

**总体**：代码质量高于预期——数学正确（逐元素 1e-17 级）、
没有硬编码数字、没有测试专用分支、边界处理扎实（19/19 不抛）、
持久化严格无损（0.000e+0）。
主要问题在**能力表述**（"按意思像不像"）与**默认参数**（θ 偏低导致重复仍写），
两者都不影响契约达标，但会影响使用者的期望管理。
